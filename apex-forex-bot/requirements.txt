# Pinned to the versions currently running in production, read from the live
# Render build log — so these are known to resolve and install on the
# deployment's Python, not guessed.
#
# Why exact pins and not ">=": Render runs `pip install -r requirements.txt`
# on every build, so a floor alone means any upstream release ships itself
# straight into a live trading bot with no review. Twice in one day a
# transitive upgrade broke this project's own tooling. Reproducible builds are
# the point — bump these deliberately, not by accident.
#
# Every entry below is imported at runtime; the list was checked against the
# actual import graph. The `groq` SDK used to be here and was never imported:
# the Groq calls go out over plain `requests`.

requests==2.32.3
redis==8.1.0
python-dotenv==1.2.2
# Field-level encryption of broker tokens at rest (Fernet, in
# apex/user_store.py — the only thing in this repository that uses this
# package). NOT the broker TLS path: that is stdlib `ssl` against the system
# OpenSSL, so this pin has no bearing on the cTrader connection.
#
# Held at 42.0.8 until 2026-09-26 by `pyOpenSSL==24.1.0`, which required
# `cryptography<43,>=41.0.5` and arrived transitively with
# `ctrader-open-api`. Vendoring the protobuf stubs removed both, so this
# became raisable. 50.0.0 is the floor that clears the last finding
# (PYSEC-2026-3552); 50.0.1 is the current patch on that line and clears
# every advisory. Fernet backwards compatibility is pinned by
# tests/test_fernet_compat.py, which decrypts a token minted under 42.0.8.
cryptography==50.0.1
yfinance==1.6.0
